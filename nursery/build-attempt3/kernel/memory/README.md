# Kernel Memory Management Subsystem

This `kernel/memory` directory contains the core components responsible for managing the system's memory resources: Physical Memory Manager (PMM), Virtual Memory Manager (VMM), and Kernel Heap (KHeap). They work in concert to provide a robust and secure memory environment for the kernel and user processes.

## 1. Physical Memory Manager (PMM)

*   **What it is:** The PMM is the lowest-level memory manager, directly interacting with the physical RAM. It tracks the availability of raw physical memory pages.
*   **How it works:**
    *   Utilizes a **bitmap** where each bit represents the status (used/free) of a 4KB physical page.
    *   **Initialization (`pmm.initialize`):** Identifies available RAM regions (e.g., from an E820 map), marks kernel code/data, the PMM's own bitmap, and other known used areas as allocated, and the rest as free.
    *   **Allocation (`pmm.allocate_physical_page`, `pmm.allocate_consecutive_pages`):** Provides functions to allocate single 4KB physical pages or contiguous blocks of physical pages.
    *   **Deallocation (`pmm.free_physical_page`, `pmm.free_consecutive_pages`):** Releases physical pages back to the free pool, updating the bitmap.
    *   Ensures thread-safety during critical operations by disabling interrupts (`pushcli`/`popcli`).
*   **How to use it:** Directly provides raw physical memory pages. Primarily used by the VMM to acquire physical pages for page tables and virtual memory mappings, and by other low-level drivers that need direct physical memory access.

## 2. Virtual Memory Manager (VMM)

*   **What it is:** The VMM is responsible for managing the virtual address space, abstracting physical memory. It translates virtual addresses (used by CPU and software) into physical addresses (used by RAM hardware) via the CPU's paging unit.
*   **How it works:**
    *   Implements a 2-level **x86 paging scheme** (Page Directories and Page Tables), where each entry typically refers to a 4KB page.
    *   **Translation (`resolve_virtual_to_physical_address`):** Given a virtual address and a page directory, it walks the page table structures to find the corresponding physical address.
    *   **Mapping (`map_virtual_address_to_physical`):** Establishes a mapping between a virtual address and a physical address within a specific page directory. It allocates new page tables (using the PMM) as needed.
    *   **Unmapping (`unmap_virtual_address`):** Removes an existing mapping and frees page tables (via PMM) if they become empty.
    *   **Page Directories:** Each independent address space (e.g., for a process) is represented by its own Page Directory (`create_page_directory`).
    *   **CPU Interaction:** Functions like `set_page_directory_register` and `enable_memory_paging_cpu_bit` manage CPU control registers (`CR3`, `CR0`) to activate and switch paging contexts. `invalidate_paging_cached_address` handles Translation Lookaside Buffer (TLB) invalidation.
    *   **Page Fault Handling (`virtual_memory_page_fault_handler`):** Catches and handles page fault exceptions generated by the CPU when an invalid memory access occurs.
*   **How to use it:** Used to set up and manage the address spaces for the kernel and all processes. It is the core mechanism for memory protection and isolation.

## 3. Kernel Heap (KHeap)

*   **What it is:** The KHeap provides dynamic memory allocation (like `malloc` in user-space) for kernel-mode components. It operates within the kernel's virtual address space.
*   **How it works:**
    *   Manages a pre-allocated region of virtual memory for its operations.
    *   Uses a **doubly linked list** of `memory_block_t` structures to keep track of free and allocated memory chunks.
    *   **Allocation (`kmalloc`):** Searches for an available block of sufficient size. If a larger block is found, it can be split. Includes debugging features (`magic1`/`magic2` numbers) to detect heap corruption. Allocated memory is zeroed out.
    *   **Deallocation (`kfree`):** Marks a block as free and attempts to **consolidate** adjacent free blocks to reduce fragmentation. Clears freed memory.
    *   Provides debugging utilities (`kernel_heap_dump`, `kernel_heap_verify`, `kcheck`).
*   **How to use it:** Kernel drivers, subsystems, and data structures (e.g., Process Control Blocks, file system objects) use `kmalloc` and `kfree` for dynamic memory requirements.

## Memory Management in the Context of Process Management

The three components work together to provide memory for processes:

1.  **Process Address Space Creation:**
    *   When a new process is created, the **VMM**'s `create_page_directory()` is called to set up a new, isolated virtual address space for it.
    *   The kernel's own memory (code, data, kernel heap) is **identity-mapped** into every new process's page directory. This ensures that the kernel's context is always available when the CPU is running in a user process's address space.
    *   The **PMM** allocates the physical pages needed for these new page directories and page tables.

2.  **Loading User Code and Data:**
    *   As the process's executable (e.g., ELF file) is loaded, its code and data segments require physical memory. The **PMM** provides these raw physical pages (`pmm.allocate_physical_page()`).
    *   The **VMM** then maps these newly allocated physical pages into the process's specific virtual address range using `map_virtual_address_to_physical()`.

3.  **Kernel Structures for Processes:**
    *   Kernel-level data structures related to processes (e.g., Process Control Blocks (PCBs), kernel stacks for processes) are allocated from the **KHeap** using `kmalloc()`. These structures reside within the kernel's constant virtual address space.

4.  **Context Switching:**
    *   When the operating system switches from one process to another, the **VMM** is responsible for updating the CPU's `CR3` register (via `set_page_directory_register()`) with the physical address of the new process's page directory. This operation instantly switches the entire virtual address space, isolating processes from each other.

5.  **Process Termination:**
    *   Upon process termination, `virtmem.destroy_page_directory()` is called to dismantle its entire virtual address space. This function systematically frees all physical pages that were part of the process's page tables and mappings back to the **PMM**.
    *   Any kernel resources for the process allocated from the **KHeap** are freed using `kfree()`.

This layered approach ensures memory safety, isolation between processes, and efficient resource utilization within the kernel.
